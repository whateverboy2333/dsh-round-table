# dsh-round-table

**中文** | [English](README.en.md)

DeepSeek Harness 圆桌会议插件。让已有 Agent 窗口围绕同一个目标讨论，由你选择资料、安排处理顺序、验收结果，再交给独立秘书整理纪要。成员继续使用原窗口和上下文；可从宿主已声明的 Agent 预设新建骑士，无需安装 dsh-flat-teams。

## 安装

圆桌骑士 **0.1.18** 面向官方 Windows 桌面版 **DeepSeek Harness 0.2.0-rc.2** 的 desktop profile。已通过124套常规回归、225项浏览器检查及正式桌面验收。旧 Web rc.6不受本版支持。桌面版本会校验并清理已确认删除的专属秘书全部支持日志代际，避免升级留下的旧日志令秘书重新出现。

`dsh-round-table@0.1.18` 已发布到 [npm](https://www.npmjs.com/package/dsh-round-table)。推荐使用下述桌面插件安装方式；也可从 [v0.1.18 Release](https://github.com/whateverboy2333/dsh-round-table/releases/tag/v0.1.18) 下载 `.tgz`，通过本地 `file:` 地址安装。正式桌面与 Web 宿主不要同时读写同一 DSH_HOME。使用升级前完整数据备份才能回退会话存储格式。

使用与本插件匹配的 DSH 环境：`@deepseek-ai/cordis` **4.0.4**，相关 `@deepseek-ai/dsh-*` 组件 **0.2.0-rc.2**。插件拒绝未知运行时版本；升级 DSH 后应重新验证兼容性。

推荐在桌面版「插件」页选择添加插件，填入 `dsh-round-table@0.1.18`，检查安装目标为 **desktop**。也可使用本地安装包地址，例如 `file:C:/Downloads/dsh-round-table-0.1.18.tgz`。安装完成后从应用菜单或托盘选择**退出**，确认应用已完全结束，再重新打开。仅关闭窗口可能仍在托盘运行，不能代替重启。打开侧栏「圆桌」核对版本与原会议。

如果需要命令行，请使用桌面发行版自带的 CLI。先完全退出桌面版；不要直接照抄 PATH 中的 `dsh`，它可能来自 Hermes 或旧 Web 安装。以下为 Windows 默认安装路径，若安装到其他位置请按实际位置调整：

```powershell
$desktopCli = Join-Path $env:LOCALAPPDATA 'Programs/DeepSeek Harness/resources/runtime/cli/bin/dsh.cmd'
& $desktopCli --version   # 本版要求 0.2.0-rc.2
& $desktopCli plugin --profile desktop add 'dsh-round-table@0.1.18'
# 重新打开 DeepSeek Harness 桌面版，不启动 web profile
```

本仓库根目录就是插件源码。内部开发工作区对应 `plugins/dsh-round-table-desktop`；公开仓库保留源码、构建产物及必要构建/包检查脚本，内部验收脚本与业务数据不公开。使用 npm 锁文件，构建并打包后按上方桌面 GUI 安装。

```powershell
cd C:/path/to/dsh-round-table
npm ci
npm run typecheck
npm run build
npm run verify
npm pack
```
运行需要 Node.js **^22.19.0 或 >=24.0.0**；桌面宿主实际使用24.18.1，构建与回归使用22.23.1。源码开发若使用Node 24，建议24.11.0或更新版本，以满足锁定的构建依赖。公开仓库的 `npm run verify` 提供类型和包内容检查；上述124套回归与225项浏览器验收在隔离开发工作区完成，未以正式会议发送或模型调用代替验证。

## 开一场会议

1. 打开「圆桌」，填写标题、目标和背景，选择会议默认工作区。邀请已有窗口，或从宿主已声明的预设新建骑士；新骑士可以分别选择工作区。创建会发送入会简报，普通成员可能回应。也可明确确认创建空会议后再加人。
2. 每场会议自动建立独立的「秘书·会议名」，使用默认工作区。秘书不参加普通讨论，不接收成员任务，圆桌不提供秘书单聊入口。初始化失败时在原会议重试，无需重新建会。
3. 在讨论页写内容。没有选择成员时，「记录到会议」只保存；输入 `@` 后从菜单选人，核对正文、引用和附件，再点击「发送给…」。默认发送普通讨论消息，不创建工作任务、不要求认领或提交成果，也不消耗流程任务次数额度。只在正文写出 `@姓名` 不会自动选人或执行。
4. 查看每位成员的消息接收状态。普通消息通过原窗口的 FIFO 接口排队，不打断正在处理的内容；成员可用 `meeting_reply_message` 回传本次被明确授权的回应，可多次反馈。普通回应不会自动成为正式成果，也不自动公开原窗口其他私聊。正式工作先通过「任务卡生成」由已@原成员提出卡片，核对后明确发布；普通回复和标记结论不自动唤醒其他成员；正式结果满足条件时，既已授权且勾选自动的下游可按规则继续。
5. 打开纪要页，选择「全量」或「自上次以来」，生成草稿。核对来源、系统任务快照及正文后，再决定公开到会议、发送通知给成员，或导出。公开只新增记录，不唤醒成员；通知会向成员原窗口发送内容。可一直保留草稿。

讨论保留主要阅读空间；紧凑会议头提供管理与下一步入口，页面导航与讨论工具分组显示。成员在当前页右侧边栏中查看：成员列表 → 详情 → 会议工作日志，不再跳独立成员页。宽屏并排，窄屏覆盖并可收起，打开边栏保留讨论滚动、搜索与未发送草稿。资料、纪要和设置仍有各自入口；任务卡全文、版本和发布使用「任务卡」弹层。会议列表支持搜索、置顶、待处理提示与归档查看。

列表区分历史待验收、需核实／故障与执行中，可按状态筛选。会议头提供下一步入口；流程完成后默认页面明确标识下一轮草稿，不代表重新执行。纪要先展示摘要、决策、责任与下一步，系统核对和生成证据可展开；历史正文保留。

批量添加预设成员会逐项记录会话身份与创建进度。部分失败后重试只继续未完成步骤，已有成员不会被重复新建或再次简报。建会后成员失败也继续原会议；新建会响应丢失时使用“重试原创建请求”恢复同一会议，不能另起一次创建。旧版未记录请求身份时仍须先核对列表。

## 准备任务、修改与验收

每次打开圆桌从默认380px侧栏开始，原Agent页面与圆桌并排重排；本次可拖拽调整，关闭重开恢复默认尺寸，会议选择与草稿保留。「打开完整工作台」铺满左侧会话栏右边的内容区；「收回侧栏」返回本次的侧栏宽度。关闭或卸载释放原页面的空间。

在讨论输入区 @选择原成员，点击「任务卡生成」。额外正文可留空；只有明确选中的引用和材料随请求输入，成员依据实际收到的本会上下文生成后续工作。每个待办是一张独立的详细Markdown卡，多成员分别返回各自清单；失败时只重试该成员原请求，不重生成成功项。

「任务卡」弹层显示生成成员、责任成员和完整正文。可直接编辑，或只让这张卡的原生成者调整。原稿、用户修改和调整建议保留版本；晚到建议不覆盖正在编辑的文字。先保存并核对责任成员，再勾选要执行的卡片。**确认发布即通知选定责任成员执行**；先将批准版本写入会议目录，再建立任务和投递。生成、编辑和采纳均不执行。新请求不能重发同一卡版本；发布响应丢失保留原批准请求，恢复只使用同一请求。

新会在选择的工作区建立「会议名＋稳定标识」目录，包含会议说明、文件索引、材料、任务卡、成果和纪要。改名不改目录身份。原成员可通过只读会议工具跨工作区读取精确批准版本；秘书继续禁工具，由插件读取并核验实际文件快照后注入。缺失、篡改或索引损坏时停止使用相关输入，不凭文件名猜测内容。历史会需在资料页明确关联并保存历史文件，不重投或执行旧任务；归档、删除会议保留用户工作目录。

草稿和待核实请求按当前DSH实例分区。旧手动任务编辑与模板入口已替换；历史要求、结果和日志仍可查看，旧版已确认但结果不明的原请求可核对恢复。存储不可用时不新发无法恢复的任务卡请求。「找回旧草稿」可预览或复制原文，所属未知时不猜测导入。

在讨论工具栏直接点击「导入成员回复」，选择来源成员后主动读取真实 assistant 回复，预览并确认用途：「加入会议」只新增会议记录，「补交任务」只补交选定的未完成任务。来源成员、原回复序号、时间与摘要校验保留；取消不改变会议，导入不通知其他成员，私聊实况不会自动成为正式资料。正式成果也可由成员工具明确回传。

进行中的工作仍可从关联消息发普通澄清或补充；`contextTaskId` 仅关联原任务，不另建任务、不改写冻结要求，也不因等待正式结果而阻止普通问答。成员边栏的「会议工作日志」集中展示本会要求、选定资料、投递、回应、正式成果、关联修改和验收记录；历史离会成员记录保留，日志不自动读取其他私聊。

「要求修改」使用可恢复的同一份意见草稿，可从成员工作日志和进程查看。确认后向原处理成员发送关联修改任务；原结果保留，待办跟随最新修改结果。明确拒绝发送时保留意见并可重新预览；送达不确定时应核对原请求。结果已提交不等于验收通过；旧图验收/退回/修订关口保留，新自由步骤无评审模板预设，正式可用成果可供已授权自动下游使用。已冻结的历史输入不改写。

## 安排会议进程

新步骤列表从空白开始：添加环节，直接点击标题命名，在每行选择成员Agent。同一成员可以负责多个环节。任意环节旁的「设置并行」可增加同时进行的独立步骤，所有分支正式完成后再进入下一阶段；支持插入、移动阶段与删除。每个环节标题栏常驻「删除」，无需展开详情；并行分支可逐项删除，删到一项恢复普通步骤，删到零项回到空白。删除修改编辑草稿，保存后更新会议配置。没有预置评审、决定、秘书或返工结构，需要修改时自行添加后续步骤。

进程页将「正在查看」「显示方式」「流程配置」「本轮运行」分组。保存配置／保存修改只记录安排；预览并启动本轮仍需确认。暂停时「继续本轮」只恢复已确认工作，未保存修改不会用于执行。停止与完成在「运行操作」中；历史记录明确只读。整理图形仅在流程图工具条中改变布局。

1. 为环节选择成员，在展开详情填写要求和会议资料，再保存。尚未命名或指定成员也可保存为草稿；启动预览须补齐配置。保存不执行任务。
2. 每个步骤仅提供“自动接收上游信息并运行”，默认关闭。先保存，再预览并确认启动本轮；勾选环节满足条件后接收所走上游的正式输入并运行，未勾选环节须手动预览确认。普通新环节可使用正式提交结果，已配置的验收／人工选路／开始确认关口仍停下；未验收的记录不自动标通过。失败、不确定、成员失效、额度及自动轮次上限处停止。保存未来规则会暂停本轮，核对后明确继续；重启不自动续跑。生成草稿和普通回复不代替批准卡或正式结果。
3. 已有会议的原流程及运行历史保留，步骤列表按实际旧节点只读展示；可查看原流程图，继续使用原图配置。结束本轮后可「新建空白步骤编排」，保存前仅改变本地草稿。新步骤流程图只用于查看依赖，在步骤列表编辑。已开始环节及本轮顺序/并行结构保持冻结，未来字段变更按确认和暂停规则保存。

默认每环节每轮2次尝试、每次运行30次普通投递预留和5次秘书生成发起。可确认追加累计额度；追加不开始任务、不重置已用次数。传输重试和临时点名也计入额度。**执行次数和输入字符数不是 Token 或费用硬上限**，一次成员任务仍可能包含多次模型和工具调用。

在进程页具体环节中补充资料，只暂存到所选环节；自动运行会暂停供核对，明确恢复后才继续。绑定已发布卡片并启动环节是一次新的工作授权，可能再次执行该卡，请核对已有任务。临时点名不完成计划节点。「使用已有结果继续」明确省略缺失分支，「跳过处理并沿用输入」保留跳过说明，均不把跳过当作成功。

## 资料与纪要

资料页列出本会成功上传的全部文档、图片及历史版本。上传后即归档，是否发送给成员、是否从输入草稿移除引用都不影响归档；同内容的不同文件名分别记录，完全相同的上传重试复用原记录。建会时工作目录暂不可用，按原请求恢复后会补齐此前已上传资料。旧会接入目录仍需明确确认。

普通文件（包括RAR等压缩包）可保留完整原件与文件引用，最大256MB，按512KB分块加载并核验SHA。不自动解压或解析，不把二进制内容塞进模型；正文只输入明确的引用元数据。图片和小文本仍使用原读取协议。未知网络错误可使用同一原文件加载身份重试，大小等确定性限制不提供无效重试。删除小叉只移除草稿引用，原件保留；点击引用可核对版本与下载完整原件。

草稿引用使用原生样式：64px圆角图片缩略、悬停或聚焦小叉，以及蓝色文件图标与名称，放在同一个输入框内。小叉或聚焦附件后Delete／Backspace移除当前引用，正文首位Backspace可撤回最后附件；不删除归档原件。关联来源仍先确认影响，输入中部编辑与IME不误删，图片可就地打开原图。

图片及文档直接拖入圆桌讨论区，无添加按钮。仅圆桌区域接管文件拖拽，进入时复位宿主拖拽遮罩；移到插件外仍由原Agent附件区接收。只读、待核实、模态及其他页面拒绝加载，不回落原会话；文件路径不进入正文。支持格式与大小限制保持，加载仅归档并加入草稿，明确发送后才通知。

Agent只读工具仅向真实、未归档的当前成员、本人的可信创建会议或该会专属秘书开放。普通成员不能通过工具自行加入陌生会议，也不能邀请其他成员；本人可信创建会议的Agent可邀请。历史会议不推断创建者，成员管理通过宿主用户界面完成。入会简报先批准职责与说明版本，再以稳定消息身份排队；送达不明只核对持久回执，不盲目重投。

- 讨论区支持直接拖入文件及粘贴图片，显示缩略图或文件预览，可移除或逐项重试。上传仅归档，不唤醒成员；正文和图片在同一条发送中提交。未完成或失败上传阻止发送，其他草稿内容保持不变。附件单独发送需明确选择发送或仅记录。
- 资料支持 UTF-8 文本、Markdown、代码、diff/patch，以及 PNG/JPEG/WebP。直接解析的图片和文本每份最多2MB，文本最多10万字符；普通完整文件引用最多256MB。同名新内容保留版本和 SHA-256，放行使用选定版本。PDF/Office可保留完整文件引用；如需模型阅读内容，请另行提供文本。
- 图片要求宿主模型适配器声明支持图片；当前 DeepSeek 适配器不支持，会提前拒绝。移除随消息携带的附件可能同时移除正文引用，界面会列明影响并要求确认。
- 纪要默认读取本会已公开资料，包括普通问答；普通回应不计作已完成任务。读取原会话回复需在设置中明确确认，范围限于参会时段；同一会话仍可能包含其他工作，需要判断来源。流程秘书使用本轮冻结的指定资料。
- 系统提供任务数量、成员、提交和验收状态快照，并提示能确定的正文冲突。**这不能证明全部生成内容正确**；建议、决策、遗漏和含糊数量仍需核对。确认保留已知冲突后，公开、通知和导出都会带上冲突说明。
- 增量以最后成功生成的纪要为基线，与是否分享无关；首次增量回退全量。取消或失败不推进游标，来源切换不混用基线；失败来源保留旧游标以便补读。
- 长文本分段处理，没有最近若干条的截断。部分来源失败会提示，全部读取失败则失败；空会议直接生成暂无内容，不调用模型。生成使用默认模型，每次子调用输出预算6000 tokens，输入分段约16000字符，最多128次子代理调用；超过预算明确失败，不保存伪完整纪要。这些生成预算不构成整场会议的费用硬上限。

## 投递与恢复

| 状态 | 含义与下一步 |
|---|---|
| `queued` | 已授权，等待原窗口空闲或前一任务结束 |
| `offline` | 本次尚未投递，原会话恢复失败或状态需核对；在成员边栏查看原因并重试恢复 |
| `delivering` | 正在投递并核对宿主落盘记录 |
| `delivered` | 已确认送达，等待正式结果；不表示已读或完成 |
| `uncertain` | 不能证明送达，先检查原窗口；确认重试可能重复执行 |
| `in_progress` | 成员已认领执行 |
| `completed` / `failed` / `cancelled` | 已提交结果、失败或会议等待已结束；验收是独立状态 |

上表为正式工作任务状态。普通消息单独记录接收状态：已送达只证明原窗口接收，不要求提交工作成果；送达待核实先核对原消息，无法证明时不盲目重投。

确认执行后，插件先核对宿主权威会话和工作区信息；原成员尚未加载时，通过宿主入口恢复同一会话 ID、原上下文、工作区和 Agent 预设，无需先手动打开原窗口。归档或已删除的原会话不会被自动恢复，不创建替代会话；读取失败显示状态未知，不推断删除。忙碌窗口保留排队。成员边栏显示恢复中、失败和原因，可重试恢复；移出成员前列出受影响任务与流程节点，确认后结束本会未完成等待、保留历史，不把缺失成员视为完成。新建骑士仍需核对实际工作区归属后才入会。

暂停放行队列阻止新放行、重试和队列投递；恢复会继续此前已授权的队列。暂停、结束等待、退会和停止流程都不会停止普通成员原窗口。设置中的即时广播／派遣是独立的立即唤醒入口，仍需单独确认。重启后流程暂停，中断的纪要任务标为失败，可手动重试。

## 归档、删除与使用边界

归档保留资料和普通成员会话，结束本会未完成等待与流程，取消纪要生成。恢复后队列保持暂停，不重新打开已结束任务。批量归档确认名单后逐项显示结果，失败项可重试。

永久删除需二次确认，可选择是否通知普通成员。删除会议状态和专属秘书主会话日志，保留普通成员原窗口；取消正在生成的纪要，等待已有写入排空。失败保留删除进度供重试，**没有回收站**。秘书日志删除支持宿主 JSONL 后端；其他入口持有秘书句柄时需重启 profile 后重试。历史一次性子代理日志不额外清除。

- 所有成员需在同一个 DSH 进程。**同一 DSH_HOME 仅运行一个圆桌队列宿主**；不同 profile 名称默认不隔离会话、会议和存储。开发验收使用独立 DSH_HOME。
- 不支持跨机器协作或定时纪要，不承诺跨进程 exactly-once。送达不确定后重试可能重复；成员不回传时保持等待，不能靠私聊推断完成。
- 资料选择控制本轮主动投递内容，原窗口保留上下文。会议文件工具只开放本会已批准版本的只读访问；不会开放任意路径，也不隔离成员原来拥有的上下文和其他文件权限。
- 原生侧栏可能显示秘书。秘书工具限制仅在插件运行期间生效，卸载后不继续约束原生会话权限。
- 场景管理插件可能停用未列入当前场景的第三方插件；圆桌入口消失时，先检查当前 profile／场景的插件启用状态。


讨论正文按Enter执行当前发送／记录按钮，Ctrl／⌘＋Enter在光标或选区处换行。Shift＋Enter也保留换行；输入法选字、@选人和禁用状态不误提交。

旧运行沿用冻结规则，历史不改。原图逐环节开关仍兼容schema2；自由步骤编排需用户明确新建，保存为schema3，旧插件对此只读、不能投递。旧保存定义会保留在版本记录中，当前插件兼容1/2/3，未知4+只读。
